Measurement setup and evidence

Download size is the exact Chrome or Firefox ZIP. Startup JavaScript counts the scripts loaded by the popup. Runtime charts use a production React profiling build with simulated tab metadata, repeated observations, and the same workload for each compared version.

Startup and search use the selected tab count. Group dragging and post-drag heap always use 1,012 tabs. Search includes the application's debounce; heap is measured after garbage collection. These observations do not measure native browser API latency, website loading, cold browser launch, or total browser memory.

Runtime comparisons require the same browser, runner, harness, and fixtures. Choose a measurement series to see compatible observations; missing points stay unavailable. Timing differences are advisory. Whiskers show the observed minimum and maximum, not confidence intervals.

New captures also measure the fixed 3.0.0 reference alongside the candidate and its preceding release. The series selector shows how many versions share the protocol. Browser, hardware, or harness changes create a separate series; their absolute timings are not silently connected.

New reports are stored as uniquely named assets on the app's GitHub release. The website loads and validates them during its build, then serves a static snapshot. Chart interactions make no requests to GitHub. Download the original records below for raw samples, hashes, and provenance.

Historical timing backfills measure the frozen release sources today, using one common simulated browser adapter. They are not observations from the original release dates. Original published ZIPs and rebuilt source packages are identified separately in the table.
